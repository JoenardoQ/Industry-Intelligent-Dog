## 审批目标

本审批包把完整产品重构划分为五个相互衔接的子项目。批准后，执行阶段按 `1 → 2 → 3 → 4 → 5` 连续推进；子项目内部严格执行 RED、GREEN、回归、规格审查和代码质量审查。除非遇到需要新增外部权限、不可逆数据操作、付费调用或发布动作的真实阻塞，不再逐项要求设计批准。

用户可在本文件末尾选择“本地连续实施”或“完整交付”范围。“本地连续实施”只授权修改本地源码、测试、文档和构建配置，并运行不产生付费的本地验证；“完整交付”还授权在门禁通过和 `$clean-before-commit` 无阻塞后创建普通 commit、push 到 `origin/main`、触发已有三平台 CI，幂等复用或更新现有三个平台 Issue（不存在时才创建）和对应公开 Beta Pre-release，并在检测到有效本机登录时使用现有订阅 Agent CLI 执行一次固定、无用户数据的有界烟雾。两种范围都不授权 force push、改写历史、签名、公证、API 计费调用或删除用户生产数据。

## 共同产品边界

- 产品是可安装的 Windows、macOS、Linux 本地优先桌面应用，不是仅供开发者运行的源码工程。
- 无 API Key、无模型时仍能通过公开且无需凭据的信息源完成最小有用流程。
- 不实现邮件推送、云同步、团队协作或 IntDog 云账户。
- Agent 结果先人工复核，再成为候选证据；只有引用语义支持、可复现证据定位、数值/单位/口径一致、声明类型所需独立佐证及其他适用门槛全部通过后才能提升为正式事实。
- 来源检索至少两轮，使用中英文查询和缺口驱动扩展；网络、限流、预算错误只能暂停，不能算收敛。
- 每类来源以 8–10 个合格发布者为目标，但质量门槛优先；不足必须显式报告，不用低质来源凑数。
- App 窗口关闭后，已授权的定时任务由本机后台服务继续执行。
- 三平台 Beta 必须来自同一 Git revision，并在各自原生 runner 通过生命周期验证。

## 子项目 1：权威契约与 Agent 证据闭环

**目标：** 消除 Agent Bridge 的匿名合同和文件扫描状态，把 Agent 输出拆成可审查、可核验、不可越级的断言与引用。

**主要产物：**

- Schema 14：Agent 结果、断言、引用、复核记录；旧 JSON 保持不可变并幂等索引。
- 强类型 Pydantic/OpenAPI API，限制 Profile、任务包、结果尺寸和路径边界；可扩展能力 Manifest 安全发现并区分 direct、handoff 和 import-only。
- 状态机：`draft_review_required → rejected/opinion/submitted_for_verification → candidate/disputed/accepted`。
- 声明级核验门槛：引用可达与身份、时间/实体/冲突、语义支持、证据定位、数值/单位/币种/期间/口径，以及按声明类型确定的独立佐证；仅 accepted 才进入 Fact 投影。
- 研究助手中的逐断言复核 UI、引用链接和失败原因。

**实施任务：** 持久化与迁移；强类型 Bridge；断言核验；复核 UI 与合同生成；Agent 能力目录、安全发现与分级适配，共 5 项。

**验收重点：** 有效 URL 不等于有效证据；`partial/unknown` 语义支持、缺少定位、数值限定不一致或佐证不足只能保持 candidate；Agent 自报 tier 不作为来源身份；不可从 draft 直接 accepted；重复导入不丢复核；OpenAPI 不返回匿名 `{}`；路径攻击和损坏文件有确定错误。

## 子项目 2：数据可信度与来源覆盖引擎

**目标：** 把来源发现从单次 prompt 变成有账本、有停止条件、有人工边界的持续检索与治理系统，同时修复 Document/Assertion 去重和冲突处理。

**主要产物：**

- Schema 15：来源活动、查询、候选和审查历史。
- 九类来源的中英文查询族、权威基线轮和缺口扩展轮。
- 发布者身份、所有权、代表性、覆盖贡献、访问状态和周期复核。
- 官方一手来源的严格自动激活边界；媒体、自媒体、领导者和个人来源必须人工审查。
- URL、内容、转载、跨语言事件、同所有者站点的稳定去重与冲突组。
- 实体/产业链覆盖矩阵、扩展前沿、身份消歧、证据化关系，以及来源活动 API 和审查工作台。
- Story 跨日不可变观测、昨日差异、七日动量和 IntDog 自身七/三十日质量漂移；Parquet/DuckDB 仅保留可测触发器，不作为当前依赖。

**实施任务：** 活动持久化；两轮状态机；来源审查；去重冲突；实体与产业链覆盖；API/UI；信号动量与漂移，共 7 项。

**验收重点：** 候选池大于最终目标；连续两轮无新增合格来源/实体/关系/覆盖单元才能收敛；403/429/超时为 paused；输入顺序不改变去重结果；国内来源缺口优先但不牺牲可信度；实体广度和高价值端点深度均有证据化门槛。

## 子项目 3：后台任务与恢复

**目标：** 用持久任务账本和系统级本机调度替代依附窗口/API 进程的调度，使关闭 App 后任务仍可运行且不会重复执行。

**主要产物：**

- Schema 16：统一任务账本、租约、检查点、尝试和触发来源。
- `worker --once` 无界面入口；App 调度与 Worker 并发时只有一个获得租约。
- 每日 04:00 边界和周/月/季/半年/两年/五年按上次成功时间计算的周期规则；两年约 3,000、五年约 8,000 的 3–5 条/日自适应密度和时间桶门槛。
- Windows Task Scheduler、macOS LaunchAgent、Linux systemd user timer 适配器；后台凭据通过一次性匿名管道传递，不进入 argv、环境变量或文件。
- 任务中心与系统页的后台服务、权限、最近/下次运行、暂停、重试和恢复状态。

**实施任务：** 任务账本；一次性 Worker 与时间边界；三平台服务；状态 API/UI，共 4 项。

**验收重点：** partial 不推进成功边界；DST、时区变化、双 tick 和崩溃租约可恢复；长周期至少覆盖 90% 适用月桶且不以重复/低质条目凑数；canary 凭据不出现在 argv/env/日志/账本/状态/临时文件，权限撤销阻止新领取；邮件始终禁用；卸载应用不删除用户行业数据。

## 子项目 4：完整用户工作流

**目标：** 把已有零散能力整理为第一次打开即可理解、日常可操作、错误可恢复的完整研究工作台。

**主要产物：**

- 生成的 OpenAPI 类型成为唯一前端合同，删除平行手写 DTO。
- 四步首次引导：数据目录与隐私、行业、无模型/Provider/Agent、第一次任务。
- 行业概览整合知识结构、信息源、文档、实体和有向产业链，并提供可点击下钻。
- 每日情报支持 04:00 窗口、标题/类别/来源/时间排序、全选/多选/恢复删除和准确来源署名。
- 来源、知识、周期产物、研究助手、Intelligence Lab、任务中心和系统状态闭环。
- 成熟开源 Markdown 解析链支持目录、GFM、引用回链、搜索和可视化 sidecar，并安全过滤 HTML/URL。
- Markdown 与无需后端/CDN 的自包含单文件 HTML 简报；独立成品质量门检查证据、具体摘要、日期/来源、重复/占位、sidecar、链接和锚点。
- 现代、低饱和、可读的响应式设计系统和键盘/缩放/长文本可访问性测试。

**实施任务：** 前端合同；引导与概览；情报/知识/来源/产物；研究/Lab/任务/系统；设计与真实 renderer 烟雾；便携简报与成品质量门，共 6 项。

**验收重点：** 每页区分 loading/empty/partial/stale/error/ready；后台任务不阻塞导航；行业管理可恢复；六个周期是平行直达按钮；长文本、Markdown、下拉菜单、列表和 200% 缩放可读；报告和图表不是占位符。

## 子项目 5：三平台产品化与 Beta 门禁

**目标：** 从同一源码版本生成三个真正可安装、可首次运行、可连接 Agent/Provider、可后台调度的 Beta 包。

**主要产物：**

- Windows x64 NSIS `.exe`、macOS arm64 `.dmg`、Linux x64 AppImage。
- 包含 API、CLI、Worker 和运行资源的冻结 sidecar 及显式资源清单。
- 安装、首次启动、具有确定 oracle 的真实公开免凭据采集、虚拟安全凭据、后台服务、关闭重开、持久化、卸载保留的生命周期烟雾。
- 本地参考 Agent/API harness 合同和至少一种经授权、已登录真实 Agent CLI 的有界脱敏烟雾；mock 不能替代真实 Agent 验收。
- 三平台 CI 的路径过滤、SHA-256、测试报告、同 revision 门禁和签名条件。
- 完整且对齐的中英文 README、安装、首次使用、Agent/API、后台权限、故障排查、卸载和数据位置说明。
- 对旧 Worker、WSL/Tk 开发入口、明文配置脚本、过期 fixture 和构建垃圾进行引用/替代审计后再退役；保留有回归价值的测试。

**实施任务：** 冻结运行时；安装包生命周期；CI/制品证明；双语文档；旧架构审计退役；最终发行门禁，共 6 项。

**验收重点：** 任一平台失败则不发布；未签名 Windows/macOS 只能是带警告的 Pre-release；稳定版必须满足签名要求，macOS 还需公证；Release 不得早于原生证据。

## 风险驱动测试模型

测试集按以下维度组合，而不是只覆盖理想路径：

- 数据状态：全新、旧 Schema 13、重复导入、部分写入、冲突、损坏、超限。
- 时间状态：首次运行、有上次成功、周期不足、跨 04:00、DST 跳过/重复、时区改变、长周期稀疏采样。
- 运行状态：前台、窗口关闭、重复唤醒、崩溃、重启、暂停、取消、退避耗尽。
- 连接状态：无模型、CLI、API、MCP、凭据缺失/失效、限流、离线、登录墙和付费墙。
- 来源状态：官方、媒体、平台、自媒体/个人、所有权重复、跨语言转载、URL 变体、低质量候选。
- UI 状态：loading、empty、partial、stale、error、ready；键盘、长中英文、窄屏、200% 缩放。
- 平台状态：Windows x64、macOS arm64、Linux x64；路径空格/Unicode、安装、升级、后台注册、卸载保留。
- 安全状态：路径穿越、恶意 URL、超大输入、日志/环境泄密、打包混入数据、危险 shell 参数。

不可省略的跨域场景包括：旧库升级后重复 Agent 导入；来源活动遇到 429 后恢复；App 与 Worker 同时领取跨 04:00 任务；后台运行生成产物后重开 UI；跨语言转载去重但保留发布者关系；Agent 冲突断言不能覆盖 accepted Fact；无模型首次流程；三平台安装后凭据、后台服务和数据保留生命周期。每个场景必须能追溯到规格条款、自动化测试或明确记录的原生 runner 证据。

## 执行和汇报规则

1. 执行采用 `$self-iteration` 的文档—实现—验证闭环和 `superpowers:subagent-driven-development` 的逐任务双阶段审查；每个任务测试先行，先让目标测试失败，再做最小实现并运行相关回归。
2. 每项实施完成后先做规格符合性审查，再做代码质量审查；重大问题必须修复后才能进入下一项。
3. 重复且机械可核验的工作在运行时明确支持并确认切换成功时优先交给 GPT-5.6-Luna；本次环境未提供可验证的切换接口，因此不得声称已使用 Luna 或 `ultra`。
4. 不以“测试很多”代替风险覆盖；最终完整性声明必须附覆盖模型、缺口和原生证据。
5. 不修改真实行业数据；迁移和全流程验证使用隔离临时数据目录与 fixtures。
6. 若本地环境无法产生 Windows/macOS 原生证据，执行将停在 `NOT_READY_PENDING_NATIVE_GATES`，不得伪称三平台完成。
7. 用户已选择“完整交付”范围，因此普通 commit、push、CI、幂等复用或更新现有平台 Issue（不存在时才创建）和公开 Pre-release 已满足实施计划的外部动作授权点；发布仍以所有原生门禁成功为前置条件。

## 一次性批准语义

可一次性选择以下一种明确授权：

- 回复“批准五个子项目并连续执行”：批准五份规格、五份计划、执行顺序和本地修改/验证边界；不授权外部 GitHub 写入。
- 回复“批准五个子项目并完整交付”：除上述内容外，还授权无阻塞审计后的普通 commit、push 到 `origin/main`、已有三平台 CI、门禁成功后幂等复用/更新现有三个平台 Issue（仅缺失时创建）及对应公开 Beta Pre-release，以及在有效本机登录存在时用现有订阅 Agent CLI 执行一次固定、无用户数据的有界烟雾。本轮用户已回复同意，该授权点已满足并记录在迭代账本中。

两种授权都不允许 force push、历史改写、API 计费调用、签名/公证或删除真实用户数据。若发现这些需求或无法从现有凭据/runner 完成的外部阻塞，必须报告真实状态，不能以模拟结果替代。
