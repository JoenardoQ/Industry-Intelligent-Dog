# 子项目 3：后台任务与恢复规格

状态：已批准，待实施验证
依赖：子项目 1–2 的强类型任务和数据边界

## 目标

让每日与周期任务在 IntDog 窗口关闭后继续运行，并在系统重启、重复唤醒、任务崩溃和时区变化下保持单实例、可恢复和可审计。

## 运行模型

安装后的 IntDog 可用 `--background-worker` 进入无窗口模式。Electron 负责访问操作系统安全存储，再通过一次性、仅父子进程可读的匿名管道把短生命周期凭据包发送给同一冻结 sidecar 的 `worker --once` 模式；密钥不得出现在 argv、环境变量、临时文件、任务账本、状态文件或日志。Worker 读取一次后关闭管道，只处理到期任务，等待本次领取的任务进入终态后退出。

系统唤醒方式：

- Windows：Task Scheduler；
- macOS：用户级 LaunchAgent；
- Linux：systemd user service/timer。

注册、更新、禁用和状态检查由平台适配器完成，不拼接 shell 字符串。

## 调度与租约

- 继续使用 `automation_schedules`，新增 Worker 安装状态和最后唤醒记录。
- 领取计划必须在 SQLite 事务中比较周期键、租约和重试时间。
- Desktop API 调度器与后台 Worker 可以同时唤醒，但只有一个能获得租约。
- 每日窗口为前一日 04:00 至当前时间；周期从上次成功边界开始，历史不足时回看完整周期。
- 时区使用 IANA 名称；夏令时跳过/重复时间必须生成唯一周期键。

长周期收集使用自适应时间桶和合格文档密度，而不是把总量集中在近期。默认目标为每个日历日 3–5 条合格文档：两年 2,400–3,600 条（标称约 3,000），五年 7,000–9,000 条（标称约 8,000）；周、月、季、半年按同一密度和可用来源缩放。至少 90% 的适用月桶有覆盖，单桶不得无解释地超过中位桶三倍；真实重大事件峰值作为带理由的 overflow 保留。来源不足、重复或质量不合格时报告缺口，不复制或补造条目。

## 失败与恢复

- 权威状态集合为 `queued / running / cancelling / paused / completed / partial / failed / cancelled / interrupted`；正常完成、取消、暂停和崩溃恢复遵循上位规格定义。
- 心跳、检查点、父任务、Provider、模型、时间窗和输出位置持久化。
- 系统关机或进程终止后，过期租约可被下一次 Worker 安全接管。
- 重试遵守指数退避和上限；配置/凭据错误进入暂停，不消耗无限重试。
- 付费 Provider 或首次凭据使用需要用户预先允许后台使用；否则任务保持暂停。
- 后台授权按 Provider、行业和任务类型最小化，默认关闭并可撤销。撤销后禁止新领取、取消尚未发送请求的活动任务并清除待用凭据句柄；已经发送给外部 Provider 的请求无法撤回，UI 必须明确显示这一限制。

威胁模型覆盖普通同用户进程对命令行/环境、日志、任务清单、状态文件和临时目录的读取，以及崩溃/取消后的残留。它不声称抵御已取得管理员/root、调试器、内核或物理内存访问的攻击者。Electron/Python 的垃圾回收字符串不能可靠清零，因此实现优先使用短生命周期 Buffer/bytearray，并在使用后尽力覆盖；这一限制必须记录，不能宣称内存绝对清除。

## UI

系统页显示后台服务是否安装、最近唤醒、下次运行、权限和失败原因。任务中心区分由 App、手动、系统调度或后台 Worker 发起的任务，并提供取消、重试和恢复动作。

## 验收

- 关闭窗口后，到期任务仍能完成；重开 App 可见相同任务和产物。
- 重复系统唤醒和 App 同时运行不会生成重复任务。
- 系统重启、过期心跳、检查点恢复、取消和超时均有状态机测试。
- 两年和五年任务满足时间桶覆盖、去重、发布者多样性和证据质量门槛；不足时保持 partial/gap，不能伪报目标数量。
- Windows/macOS/Linux 平台适配器具有命令/文件合同测试，原生 runner 验证实际注册和卸载。
- 日志和环境不泄露凭据；邮件始终禁用。
- 平台合同测试和原生 smoke 必须证明密钥不在子进程 argv/env、日志、账本、状态或临时文件中，匿名管道关闭后不能重读；安全存储不可用、后台会话被锁或授权撤销时任务进入可解释 paused，而不是降级为明文传递。
