# 行业初始化工作流修复与首次使用体验

## 目标

修复桌面安装版的首次行业研究路径，使非开发者能够配置受支持的 Provider，一键启动任务，
看到真实进度，并获得完整的三阶段研究草稿或明确、可恢复的结果。

这是两轮已授权优化之前的基线修复。它不安装应用、不访问用户的真实 API Key、不发布版本、
不删除用户数据，也不会把模型输出直接变成已接受事实。

## 产品合同

直接初始化是一个顺序执行的操作：

```text
Provider 预检
  -> 信息源发现与来源门槛
  -> 产业链发现与产业链门槛
  -> 实体发现与覆盖门槛
  -> 草稿知识图谱与复核队列
```

用户不需要在中途批准任务包。每道门槛自动执行，但“可进入下一阶段”不等于“事实已接受”：

- 信息源在完成来源复核前保持候选状态；
- 产业链节点、边、实体和主张保持草稿或候选状态；
- 只有既有证据复核规则能够把记录提升为已接受事实；
- 有效网址本身不足以证明一项主张。

只有三个阶段都产生了可解析、已持久化的草稿并执行门槛，初始化才算完成。门槛失败时任务
标记为 `partial`，列明失败检查和已保留检查点，不得显示为 `completed`。

任务包模式继续保留，但必须显示“已创建任务包”，不能声称行业研究已经完成。公开免凭据
初始化仍是独立的无模型路径。

## Provider 配置与诊断

API 表单把能力清单中的默认模型作为可编辑初始值，而不只是占位符。表单拒绝空模型，也拒绝
在模型字段中填写 `OpenAI` 这类明显的 Provider 名称，同时继续允许各供应商自己的模型 ID。

API 配置完成后仍可编辑。用户可以：

- 更换模型、API Base、认证方式或 Key；
- 清除已保存的 API 配置；
- 在开始研究前显式执行真实连接测试；
- 看清测试只检查了认证，还是已经检查模型和工具调用。

OpenAI 真实探针调用已配置的 Responses 端点并验证模型。行业初始化依赖联网搜索，因此探针
也检查所需的 web-search 工具，不能只凭字符串存在就声称 Key 可用。UI 明确提示：用户主动
运行的探针可能消耗少量 API 额度。

Provider 错误在适配器边界统一正规化。界面可显示 HTTP 状态、供应商错误类型/代码、安全的
参数名、错误消息和 request ID，但不能显示请求头、API Key 或完整请求体。模型不受支持、
工具不受支持、认证、额度、限流、超时和传输错误分别使用不同类别和恢复指引。IntDog 不得
静默删除联网搜索后以更弱的研究合同继续运行。

## 阶段执行与门槛

### 1. 信息源

Provider 接收信息源发现 prompt。IntDog 解析 JSON，正规化发布者和 URL 字段，执行有界可达性
检查，并运行既有来源结构审计。优质但无法自动抓取的来源保留为人工阅读候选。

来源门槛检查候选批次的类别、发布者、地域、一手来源、URL 和可达性覆盖。通过只表示该批次
可以作为本次初始化的输入，不会自动把来源加入全局活跃池。失败时停止后续模型调用，以
`partial` 返回并列出具体缺口。

### 2. 产业链

产业链 prompt 包含经过正规化和长度限制的合格来源批次。IntDog 解析节点和显式有向边，再
运行产业链审计。节点必须具有输入、输出、顺序和引用；边必须保留自己的证据，不能借用节点
引用。门槛失败时停止实体发现并返回 `partial`。

### 3. 实体

实体 prompt 包含合格来源和正规化产业链。覆盖门槛检查每个产业链环节中带引用的实体，以及
适用的中国/海外和实体类型维度。真实覆盖缺口必须保留为缺口，不能为凑数虚构实体。成功
结果作为待复核草稿图谱持久化。

下游 prompt 中的阶段载荷必须有明确上限。过大或畸形的 Provider 输出使用类型化错误失败，
不能截断后伪装成有效 JSON。

## 状态、幂等与重试

每次初始化只有一个规范任务运行。检查点记录工作流版本、Provider/模型指纹、prompt 版本、
已完成阶段、阶段产物引用、门槛结果和当前候选活动 ID；凭据绝不进入检查点。

阶段产物先写入本次运行的临时文件，解析并执行门槛后再原子发布。只有获得有效信息源响应后
才创建来源活动，同一次运行复用该活动。在此之前失败不会产生来源活动或研究产物。

安全重试先重新执行 Provider 预检。只有行业、工作流版本、Provider/模型、prompt 版本和输入
指纹仍一致时才复用已完成阶段，否则从第一个失效阶段重新开始。重试不得为同一有效检查点
重复创建来源活动。

同一行业同时只执行一个变更型任务。后续任务按提交顺序明确保持 `queued`，不能启动后因行业
锁而失败。用户可以取消排队任务；只读浏览和其他行业的任务不受影响。

## 进度与错误呈现

CLI 只输出一种规范的机器可读进度格式，由任务运行时映射到任务账本。初始化采用以下确定性
里程碑：

- Provider 预检：5%；
- 信息源请求、验证、门槛：10%、25%、35%；
- 产业链请求、验证、门槛：40%、55%、65%；
- 实体请求、验证、门槛：70%、85%、95%；
- 原子发布草稿：100%。

等待外部请求时，UI 显示当前阶段和已用时间，不虚构阶段内部进度。日志保留有代表性的阶段
开始、门槛结果、重试决策和最终产物位置。

规范任务错误必须使用正规化后的 Provider 或门槛失败原因。通用子进程退出码只能作为次要
信息，不能覆盖真实原因。

## 桌面用户旅程

首次连接步骤和后续连接设置复用同一组件与视觉语言。已配置 Provider 显示供应商、模型、最近
探针结果，以及“编辑、测试、清除”操作。字段说明明确区分 Provider 与模型 ID，并用能力清单
默认值作为示例。

初始化页面固定显示三行阶段状态：`waiting`、`running`、`passed`、`partial`、`failed` 或
`skipped`，并显示当前消息和已用时间。终态只提供相关操作：

- 配置失败：编辑连接后重试；
- 门槛缺口：查看缺口或重新发现；
- Provider 瞬时失败：从检查点重试；
- 成功：打开信息源、产业链、实体或行业概览。

提交初始化后，同一行业的重复提交按钮禁用。其他研究操作明确说明它们会排在当前任务之后。

## 兼容性与所有权

- SQLite 继续作为任务状态和检查点的权威来源；兼容 JSON 可以暴露草稿，但不拥有工作流状态。
- 既有 `/generate`、`/jobs`、重试、取消、setup 和工作流设置 API 保持兼容；新增探针或阶段详情
  仅采用增量接口。
- 既有 Provider 适配器继续保留公开的 `complete()` 合同；共享错误正规化只在 Provider 边界
  实现一次。
- 除非实施证明现有 Python、FastAPI、React、Electron 和 SQLite 无法满足验收标准，否则不
  引入新的运行时依赖。
- README 与首次使用文档必须以结构和含义一致的完整中英文版本描述实际行为。
