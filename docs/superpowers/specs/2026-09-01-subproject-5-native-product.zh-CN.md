# 子项目 5：三平台产品化与 Beta 门禁规格

状态：已批准，待实施验证
依赖：子项目 1–4 全部通过共享本地门禁

## 目标

从同一 Git revision 生成 Windows x64、macOS arm64 和 Linux x64 安装包，并证明安装后的真实 UI、冻结 sidecar、安全存储、后台服务和数据生命周期可以运行。

## 安装包

- Windows：NSIS `.exe`，桌面与开始菜单入口，可选择安装目录。
- macOS：arm64 `.dmg`，Beta 可未签名；稳定版必须签名并公证。
- Linux：x64 AppImage，带桌面元数据与图标。
- 三个平台分别发布安装包、SHA-256、构建清单和测试报告，不把运行时或开发源码要求留给用户。

## 原生生命周期

每个平台必须在对应原生 runner：安装或挂载、首次启动、完成无模型首次任务、通过本地参考 Agent/兼容 API harness 验证连接合同、配置虚拟安全凭据、安装后台服务、关闭窗口、触发一次后台任务、重开并核对持久数据，最后卸载应用但保留用户行业数据。至少一个用户控制的原生环境还需用已登录且明确授权的真实 Agent CLI 完成一次有界深度流程；未取得该授权或登录无效时必须单独标为外部验收缺口。

“无模型首次任务”只有在隔离数据目录中以 `public_credential_free` 采集模式实际获得以下结果才通过：至少 3 个可达且身份已核验的发布者（至少 2 个来源类别）、6 篇非重复文档（至少 2 个独立发布者）、5 个实体候选（至少 3 个对象类型）、3 个有序产业链节点和 2 条带文档/断言证据的有向边。结果必须记录真实 URL、采集时间和内容哈希，Provider/API 调用计数为零；只生成 taskpack、内置种子清单或本地 reference harness 不能满足此 oracle。网络失败或公开源不足应产生明确 partial/gap 并阻断该验收门槛。

## 构建与安全

- PyInstaller sidecar 包含 API、CLI 和 Worker 入口。
- electron-builder 只包含明确资源；构建前生成 OpenAPI 类型并检查无漂移。
- 安装包和日志扫描虚拟密钥明文、开发路径、测试数据和生产数据。
- Release workflow 只接受同 revision 的三平台共享门禁成功结果。
- 未签名构建只能标为公开 Pre-release，并显示平台警告。

## 旧架构退役

在删除旧 Worker、Tk/WSL 启动器、明文 API 配置脚本、过期 fixtures 或测试前，必须同时满足：无生产导入/调用、无文档或安装流程依赖、替代路径已通过回归、用户数据不在目标中。仍提供回归价值的测试必须迁移或重写，不能为了缩小仓库而删除。开发专用入口如果保留，必须明确标记且不进入安装包。

## 文档与引导

中英文 README 和安装指南分别给出系统要求、安装、首次使用、连接 Agent/API、无模型模式、后台权限、故障排查、卸载与数据位置。App 内首次引导与文档使用相同术语和步骤。

## 验收

- 三个平台完整 Python、Web、Desktop、OpenAPI、仓库检查、sidecar、Worker 和 renderer 生命周期全部通过。
- 参考 Agent harness 的导出/执行/导入合同通过，且至少一种真实已登录 Agent CLI 的有界深度流程具有脱敏记录；mock 不能替代后者。
- `NOM-01` 无模型 oracle 的来源、文档、实体、产业链和零 Provider 调用断言全部通过；reference harness 仅验证确定性合同，不能替代真实公开采集。
- 安装包来自同一 SHA，文件名、版本、校验值和发行说明一致。
- 旧 `4.0.0-test.1` 或其他历史包不作为当前证据。
- 发行路径不包含已退役入口、开发 venv、历史构建、旧测试数据或明文配置脚本；删除清单具有可审查的引用与替代证据。
- 本轮“完整交付”批准已覆盖无阻塞审计后的普通 commit、push 到 `origin/main`、已有三平台 CI、幂等复用/更新平台 Issue（仅缺失时创建）及门禁成功后的公开 Pre-release；不覆盖 force push、历史改写、签名/公证、API 计费调用或用户生产数据删除。
