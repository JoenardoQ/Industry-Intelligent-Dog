# DomainIntelApp

[English documentation](README.md)

> 4.0：`./run_intdog.sh` 启动独立的 IntDog Web 应用窗口。本目录只负责加载窗、
> 隔离运行环境、持久任务运行时和桌面快捷方式；旧 Tk 工作台已经移除。

IntDog 的本地桌面工作台，用于管理行业、启动采集和研究、浏览数据、批量操作并生成周期产物。界面本身可离线浏览已有数据；联网研究由 `DomainIntelSearch`、Codex 登录或 API 配置提供。

普通用户应安装 Windows `.exe`、macOS `.dmg` 或 Linux `.AppImage` 原生 Beta。
下面的源码启动器仅作为开发兼容路径保留，明确不进入发行资源。

## 启动

生产环境在 WSL home 中从仓库根目录运行：

```bash
cd "/home/joenardo/My Projects/IntDog"
./run_intdog.sh
```

首次启动会创建 `.intdog-runtime/venv-linux-*`、安装锁定的前端依赖并生成生产构建；Windows 与 Linux 环境分开保存，
不会误用从旧盘复制来的虚拟环境。WSL 启动脚本会优先选择带 `tkinter` 的 Python；
当前机器使用 `$HOME/miniconda3/bin/python`。其他机器需安装 `python3-tk`，或设置
`INTDOG_BOOTSTRAP_PYTHON` 指向带 Tk 的 Python。

### Windows 入口

当前生产环境在 WSL home，WSL home 首选桌面快捷方式；它固定启动 `/home` 中的
`run_intdog.sh`。需要重建快捷方式时，在 Windows PowerShell 运行：

```powershell
powershell -ExecutionPolicy Bypass -File .\create_shortcut.ps1
```

仅原生 Windows checkout 才双击 `run_app.bat`；首次启动会创建对应的 Windows 隔离环境。

如需切换数据根目录，启动前设置 `DOMAIN_INTEL_DATA_ROOT`。

## 第一次使用

1. 在行业管理中创建或选择行业。
2. 打开“初始化行业研究”，选择 Codex 套餐、API 或任务包模式。
3. 系统依次审计信息源、产业链和实体覆盖；通过门槛后才写入下游草稿。
4. 在每日情报运行采集，再到知识结构、定期产物和行业报告查看结果。

Codex 套餐模式使用本机 ChatGPT/Codex 登录，无需 API Key。任务包模式只产生 prompt，不会直接出现完整报告。

无模型公开免凭据采集与任务包不是同一结果；前者必须通过 `NOM-01` 外部 oracle。Agent/API 生成内容
不会自动成为已审核事实。后台计划只在用户主动授权后启用，可在系统状态中撤销。Provider Key
由操作系统安全存储保存，并经一次性管道传入 sidecar，不通过环境变量泄露。Windows、macOS、
Linux 卸载程序默认保留用户数据；当前 Beta 卸载前应先停用后台服务。

## 工作台导航

默认主界面使用固定侧边栏；全局行业选择是唯一上下文，七个功能页面按需加载。宽屏使用
研究工作台布局，窄屏收起侧边栏并让表格、图谱和阅读器在各自区域滚动。

| 页面 | 主要职责 |
|---|---|
| 行业概览 | 指标链接、知识结构、产业链有向图、重点实体 |
| 每日情报 | 服务端搜索/排序/分页、当前页多选与可恢复删除 |
| 研究产物 | 周/月/季、行业报告和深度研究阅读 |
| 信息源 | 分类、健康、最近检查/成功时间与手动管理 |
| 研究助手 | 研究议程、证据、情景与 Intelligence Lab |
| 任务中心 | 持久状态与代表性日志 |
| 系统状态 | API/数据库状态、行业管理与退出 |

行业概览不以数据量代替质量：它测量来源可达性、已采集文档中国 / 国外 / 未知分布、独立印证、
实体/产业链覆盖、重复项、失败项和知识空白；缺少测量时显示 `N/A` 或待核验。
顶部状态条中的来源、文档、实体、关系和证据数量与报告文件数量分开统计。

信息源页以卡片展示名称、类别、地区、层级、采集健康和最近时间。页面支持类别筛选、
手动添加、移除、打开和跨行业复用。
兼容数据字段仍为名称、类别、来源地区、层级、访问、可达性、监测状态和发布者；Web 卡片按
需折叠字段。URL 可搜索并可通过“打开”访问，但不是显示列。
行业管理支持新建、重命名和可恢复归档，归档移入
`_trash/`，不会在页面中永久删除数据。

## 桌面信任边界与原生包

启动器生成一次性会话凭证；本地 API 只监听 `127.0.0.1`，验证 Host、Origin，并对写操作要求
会话凭证。外部导航只允许 HTTPS。退出 IntDog 时先请求 FastAPI/Uvicorn 优雅关机，超时后才
回收进程树。

原生发行采用一套 Electron 壳与一个同时承担 API/CLI 的 PyInstaller sidecar。可变数据写入
操作系统用户数据目录，不写入安装目录。Windows、macOS、Linux 安装包分别只包含本平台运行时；
打包实现位于 `DomainIntelDesktop`。

任务中心显示 `queued / running / completed / partial / failed / cancelled / interrupted`
全部状态，保留失败原因、重试参数与按需读取的输出。单次任务输出最多保存 1 MiB，达到上限
会显示截断标记；历史不会被静默自动删除，因此它不是无限日志或集中式可观测平台。

Intelligence Lab 是离线确定性计算，不显示成 Codex 生成。页面允许打开证据与来源详情、
从已有产业链节点选择直接冲击点、解释 `unresolved`、查看传播路径，并更新议程状态。
状态更新统一经过 application service；Tab/Enter/Space 可以完成主要操作。
大列表提供搜索、状态筛选、排序、滚动和分页；情景页绘制传播路径，展示启发式暴露度、
效应、边关系与证据。议程可生成任务包，但不会自动产生费用或发布结论。

不同行业可以共享同一来源；手动来源不会因自动刷新而被无故丢弃。无 RSS、付费墙或反爬的优质站点会显示为“推荐·人工关注”，它们是阅读入口，不是假装抓取成功的数据。

## 知识探索界面目标

App 提供从行业全局到产业链长尾的自由探索：

- 从行业进入子领域、产业链节点、技术、产品、企业、研究组、人物、政策和事件。
- 任一实体都能查看上下游关系、跨行业角色、时间变化、引用和相互冲突的证据。
- 产业链关系图显示节点、实体数、证据覆盖和知识空白；可在“全部/待研究”之间筛选。
- 企业与研究组同时展示头部、长尾、待验证候选和最近新发现对象，不能只固定显示 Top 10。
- 提供覆盖矩阵和“知识边界”视图，明确哪些节点研究充分、哪些只有单一来源、哪些仍为空白。
- Beginner / Intermediate / Expert 改变解释深度、术语密度和学习路径，不改变底层知识全集。

学习模块最终使用前置依赖图，关联概念、产业链节点、代表企业、研究组、核心材料、实践任务与掌握标准，而不是只提供主题列表。
所有主要操作控件必须可用 Tab 聚焦并通过 Enter/Space 触发，不使用只响应鼠标的
Label 伪装按钮。

## 生成与调度

- 每日采集写入新闻、论文、GitHub、融资、招聘和管理层动态。
- 周/月/季定期 crawl 负责聚合与任务元信息；页面上的“生成”按钮才会调用模型产生 Markdown 和图表 JSON。
- 默认 Web 工作台是唯一计划所有者：计划保存在 SQLite，应用重启后可补跑错过周期，并以租约和
  周期键避免重复入队；系统状态页显示下次运行、最近成功和错误。
- Web 调度始终设置 `INTDOG_DISABLE_EMAIL=1`，不会发送邮件，也是唯一计划所有者。

生成结果默认是 `draft_review_required`。App 不会自动把模型文本升级为已审核事实或投资建议。

Web 通过 `runtime/jobs.py` 使用持久任务目录和 Search 命令契约，
每个任务获得 `run_id`，状态原子写入 `DomainIntelData/_jobs/`；取消必须作用于整个子进程组，
并收敛为 `cancelled`，超时为 `failed`，部分采集成功为 `partial`，App 异常退出后未完成任务标为
`interrupted`。`completed` 以外的终态均不推进调度 checkpoint。App 关闭会在宽限期后
强制回收未退出的任务树，包括同步调度任务。
界面只订阅日志和完成事件，不直接管理 `subprocess.Popen`。跨重启从 checkpoint 继续仍由
具体 Search 命令负责，Job Runner 不伪造业务级恢复。

## 删除与恢复

批量删除前会明确显示选中数量。行业和可恢复数据优先移动到 `DomainIntelData/_trash/`，
不会直接永久清除；默认 Web 的系统状态页可列出并恢复行业和每日情报批次，同名行业拒绝
静默覆盖，已存在的每日文档会跳过。永久清空仍需离开 App 人工执行，并应先备份。

运行中的行业初始化、采集或报告任务不应与删除同一行业同时进行。

## 常见问题

- **界面文字或边框发糊**：优先使用系统推荐缩放；若只在快捷方式启动时出现，检查 WSL 快捷方式是否调用当前 `/home` 下的 `run_intdog.sh`，不要使用旧版打包 EXE。
- **一直显示 Planning**：初始化是多阶段任务。查看系统日志中的当前门槛和 `bootstrap_status.json`；明确失败后使用“继续初始化”，不要反复重建行业。
- **401 Unauthorized**：Codex 套餐模式需要在启动 App 的同一环境完成 Codex 登录；API 模式需要把 Key 注入 App 启动进程。
- **行业报告不显示**：任务 JSON 和 bootstrap 日志不是报告。先点击对应报告的“直接生成”，成功后刷新列表。
- **GitHub 没有内容**：该日期可能没有满足行业关键词、去重和质量阈值的项目；先检查来源和日志，空列表不应被伪造填充。
- **国内新闻偏少**：来源池会尽量提高国内覆盖，但实际事件受可达性和发布日期影响；在信息源页补充权威国内来源，并运行覆盖诊断。

更详细的命令、认证和抓取故障见 [Search 手册](../DomainIntelSearch/README.md)，数据字段与备份见 [Data 契约](../DomainIntelData/README.md)。

```bash
python -m unittest discover -s tests -v
```

UI 主要使用 Python 标准库；完整联网功能仍需要可用的 Search 环境，以及 Codex 登录或 API 配置。
当前自动化覆盖路由、响应式操作容器和业务契约；桌面视觉基线以 `1000x640` 为最低工作区。
